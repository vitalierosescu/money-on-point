# TaxHacker — Impeccable Design Context

## Design Context

### Users

Solo freelancer — Vitalie, a Belgian Webflow developer and designer. Uses TaxHacker daily to manage outgoing invoices and incoming expenses for his own business. The job to be done: create invoices fast, track what's paid and what's overdue, and keep financial admin off his mind. He works from a desk, in a browser, on a high-res display. Speed and clarity matter more than discoverability — he knows the app well.

### Brand Personality

**Sharp, clean, confident.**

The interface should feel like a tool made by a developer who cares about craft. No decoration for decoration's sake. Every element earns its place. Interactions are precise. Numbers are legible at a glance. The UI never competes with the data.

Emotional goal: **calm competence**. Looking at the dashboard should feel reassuring, not stressful. The finances are under control.

### Aesthetic Direction

**Primary reference: Linear and Vercel** — developer-grade tool aesthetics.

What that means in practice:
- Monochromatic base with near-zero accent color (charcoal, white, true grays)
- Borders over shadows for separation and structure
- Monospace font for IDs, numbers, invoice numbers
- Tight but breathable density — data-dense without feeling crowded
- Precise, consistent spacing (no random padding)
- Status indicators: small, dot or badge, never loud
- Tables feel like real data tables, not cards pretending to be tables
- Typography carries weight — font size hierarchy is clear and intentional

**Anti-references:** No gradients, no colorful cards, no decorative illustrations, no pill-shaped everything, no "startup-friendly" pastel SaaS look.

**Theme: Light only.** Dark mode support should be removed. All design energy goes into one polished light theme.

### Tech Constraints

- Next.js 15 App Router, React 19, TypeScript
- Tailwind CSS 3.4 with CSS variable tokens (HSL)
- Radix UI primitives + CVA variant system (shadcn/ui pattern)
- Lucide React icons throughout
- `--radius: 0.5rem` base border radius
- Colors defined as HSL CSS variables in `app/globals.css`

### Design Principles

1. **Data first.** Numbers, statuses, and dates should be immediately readable. Never sacrifice legibility for aesthetics.

2. **Borders, not shadows.** Use `border` for separation and structure. Reserve shadows only where genuine elevation is needed (modals, dropdowns).

3. **Mono for data, sans for everything else.** Invoice numbers, amounts, dates in tabular contexts — monospace. Labels, headings, navigation — system sans.

4. **Consistent density.** Pick a density level and hold it. Row height, padding, and gap values should be predictable and reused — not eyeballed per component.

5. **Status is never decorative.** Status badges and indicators should be small, precise, and use minimal color. A paid invoice doesn't need a celebration — just a clear green dot.

## Component Guidance

### Colors (light mode only)
- Background: pure white (`#ffffff`)
- Foreground: near-black (`hsl(240 10% 3.9%)`)
- Muted text: medium gray (`hsl(240 3.8% 46.1%)`)
- Borders: `hsl(240 5.9% 90%)` — light but visible
- Primary action: dark charcoal (`hsl(240 5.9% 10%)`) with white text
- Destructive: red (`hsl(0 84.2% 60.2%)`)
- No accent color beyond status indicators

### Status Color Convention
- **Paid / success:** emerald (`text-emerald-700`, `bg-emerald-50`)
- **Overdue / error:** red (`text-red-600`, `bg-red-50`)
- **Sent / pending:** blue (`text-blue-700`, `bg-blue-50`)
- **Draft:** muted gray (`text-muted-foreground`, `bg-muted`)
- **Cancelled:** strikethrough + low opacity

### Typography
- Headings: `font-bold tracking-tight` (page titles)
- Table headers: `text-xs font-medium text-muted-foreground uppercase tracking-wide`
- Data cells: `text-sm`
- Amounts / IDs: `font-mono text-sm tabular-nums`
- Muted context: `text-xs text-muted-foreground`

### Spacing
- Page padding: provided by layout
- Section gap: `mb-8` between major sections
- Card padding: `p-5` (not `p-6`)
- Table cell: `px-3 py-3`
- Form field gap: `space-y-4`

### Tables
- `rounded-lg border overflow-hidden`
- Header: `bg-muted/20 border-b`
- Rows: `divide-y hover:bg-muted/30 transition-colors`
- Cancelled rows: `opacity-40`

### Buttons
- Primary: dark charcoal fill, white text
- Secondary: `bg-secondary` (light gray)
- Outline: `border border-input bg-background`
- Destructive: red fill
- Icon-only: `h-9 w-9` square
- No gradient fills anywhere
